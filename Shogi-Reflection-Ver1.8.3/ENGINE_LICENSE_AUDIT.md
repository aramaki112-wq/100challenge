## Run #6 toolchain provenance decision

The exact pinned YaneuraOu commit contains a WASM GitHub Actions workflow selecting Ubuntu 22.04 and `emscripten/emsdk:3.1.43`, and its `script/wasm_build.js` material profile defines the MATERIAL build and generated JS/worker.js/WASM set. Run #6 aligns to that source-tree evidence.

The official emsdk release registry maps `3.1.43` to `bf3c159888633d232c0507f4c76cc156a43c32dc`. The bridge verifies this mapping and records actual compiler/runtime versions after installation.

## Run #5 negative evidence

Run #5 used the prior 4.0.15 bridge and successfully built/hashes assets, but Real USI failed before `usiok` with repeated `RuntimeError: function signature mismatch`; application E2E correctly degraded to ReflectionLocal. Those artifacts are evidence, not an accepted Formal/distribution build.

Changing the Run #6 toolchain to the pinned upstream 3.1.43 path is an engineering reproducibility/runtime decision. It does not waive or change any license obligation.

## GPL cautions retained

This project does not make any of the following shortcuts:

- “GPL means sale is prohibited.”
- “Free distribution is automatically compliant.”
- “WASM means GPL is irrelevant.”
- “A Worker is automatically a separate work.”
- “JavaScript messaging automatically makes everything mere aggregation.”

Where legal characterization of the combined distribution is unresolved, this document marks it unresolved instead of deciding it by architecture vocabulary.
