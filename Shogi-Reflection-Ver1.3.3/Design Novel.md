# Design Novel.md — 「消すのは、いま貼った棋譜だけ」

スマートフォンで対局を終え、KIFをコピーした。

貼り付けて、読み込み確認を開く。そこで気づく。別の対局をコピーしていた。

以前なら、画面のどこを触ればやり直せるのか、一瞬迷う。しかも「クリア」という言葉は怖い。保存してきた振り返りまで消えるのではないか、と考えてしまうからだ。

Ver.1.3.3の`入力をクリア`が消すのは、いま貼り付けたKIFと、その読み込み確認だけである。

保存済み対局には触れない。Repositoryにも触れない。LocalStorageにも触れない。Clipboardにも触れない。

この安全性は、注意書きだけで守っているのではない。Clearを担当するController自体が、保存機構を知らない。

そして、読み込み確認で少し直したいだけなら`棋譜入力へ戻る`を押す。KIF本文は残る。修正して、もう一度確認できる。

「戻る」ではない。「棋譜入力へ戻る」。何が起こるかをButton自身が説明する。

画面ではReplayを「棋譜再現」と呼ぶ。KeyPositionを「重要局面」と呼ぶ。しかしCodeの中では、長く積み上げた`Replay`と`KeyPosition`の名前を守る。

利用者の言葉と、設計の言葉は、同じでなくてよい。境界が正しければ、それぞれに最も分かりやすい名前を選べる。

盤面で「次へ」を何度押しても、Pageは棋譜一覧へ飛ばない。Ver.1.3.2で直したその感触には手を入れない。

小さな改善とは、変更量が少ないことだけではない。

**変える場所と、変えてはいけない場所が明確であること。**

それが今回の設計テーマである。
